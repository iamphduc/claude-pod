---
name: task
description: Use when the user types /pod:task [task] or asks for an ad-hoc code change outside the sprint workflow.
---

A one-off change straight to the merge-target, outside any plan: one engineer builds it test-first, the reviewer checks it, and the human merges. Never merge it yourself. Args: the task, `--merge-target=<branch>` (default: origin's default branch; pass it on), `--no-review` (for a change the human knows is trivial), and `--model=<sonnet | opus>`.

- **Docs version** first: check it per `${CLAUDE_PLUGIN_ROOT}/skills/init/SKILL.md`.
- **Browser** (the project has a UI): as in `/pod:code`'s **Preflight** (`${CLAUDE_PLUGIN_ROOT}/skills/code/SKILL.md`). Pass `browser: axi` to the engineer and reviewer with `axi`. With `devtools-mcp`, pass it to the engineer (it works alone), and before each reviewer dispatch run the app from the engineer's worktree on B/B+1, drive the browser rows the diff touches, and pass the reviewer `browser: none` with your results as **browser rows**.
- **Ports:** claim a port base B as in `/pod:code`'s **Preflight**, with `<parent-repo> task-<slug>` in the file (free once that branch is gone). Pass the engineer ports B+10/B+11 and the reviewer B+20/B+21; your own checks run on B/B+1. Delete the file after the merge.
- **Parked ideas:** the task touches one in `pod-docs/ideas/` → bring it back per **Bringing ideas back** in `${CLAUDE_PLUGIN_ROOT}/skills/idea/SKILL.md`.
- **Build:** dispatch `pod:engineer` with the task, on `--model`, else `sonnet` for small work with a clear cause, `opus` otherwise or when unsure; it sets itself up per its **Standalone** rules and keeps its worktree until the merge. The task you pass names the edges the human would check in the result, as they apply: the longest text, an empty and a full list, both themes, each branch. Its `Concerns` go to `pod-docs/handoff-queue.md` (`from: engineer`, no `sprint:`); repeat any `BLOCKED` in your hand-back. The engineer pushes its branch and opens the PR, starting the body with its `Door:` line; its report has no PR → open it yourself. Then write the rest of the PR body per `${CLAUDE_PLUGIN_ROOT}/skills/code/pr-template.md`, from its report and the branch's commits, keeping the `Door:` line.
- **Review** (unless `--no-review`): once the full PR body is written (the reviewer checks it), dispatch `pod:reviewer` with `kind: task` and every field in its **Required dispatch context** (`${CLAUDE_PLUGIN_ROOT}/agents/reviewer.md`), written as field lines, `- **<field>:** <value>`, with a long item (the task, the Repro) in an indented block under its label. `incomplete` → dispatch again with what it names; that isn't the fix pass. Its `PENDING`s go to the queue (`from: reviewer`, `to: human`). On `fix`, **one fix pass**: an engineer on `opus` in the same worktree and branch (the build engineer if it ran on `opus`, else a new one: a running agent can't change its model), with the task, its ports and browser, the PR URL, and **review findings** = the `FIX` lines. Before round 2, write the PR body again from its report, with its **Door** line and the fix commits (a one-way `undo:` also names them): the reviewer checks the body. Then the reviewer again with `round: 2`, its round-1 findings, and the engineer's summary. Then add the verdict to the PR body, and hand back, whatever the verdict.
- **Queue commit:** just before the hand-back, write this task's queue entries (the engineer's `Concerns`, the reviewer's `PENDING`s) in the task worktree, and commit them once to the task branch as one `docs(queue): …` commit. Each later round adds to that commit's entries in one new commit, never one commit per entry.
- **Hand back for merge:** the PR URL; `Review: pass`, `Review still failing` with its `FIX` findings, or `Review: skipped (--no-review)`; and that the worktree is kept, so the human can merge, fix by hand, or ask for more changes (the engineer updates the same PR) before replying `continue`.
- **After the merge:** not merged yet → end the turn again. Merged → from the parent repo, remove the worktree and delete the branch with `git branch -d`. No `--force` or `-D`; on failure, leave it and tell the human.
